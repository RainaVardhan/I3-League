## 2. Reasoning & Interpretation

- ☐ Problem statement does not prescribe the solution
- ☐ Student distinguishes assumptions from findings

## 3. Process Rigor
- ☐ Student observed before solving
- ☐ Student engaged with someone affected by the problem
- ☐ Problem was narrowed by who/where/when
- ☐ Interviewing/research process was responsible
- ☐ Team Charter exists where applicable

Rating: (same four levels)

## 4. Integrity & Reflection
- ☐ Assumptions are acknowledged
- ☐ Student shows meaningful learning
- ☐ Evidence appears honestly represented
- ☐ Consent/privacy expectations were followed

Rating: (same four levels)

## 5. Completeness
System pre-populates presence checks: ✓ Problem statement, ✓ Affected group, ✓ Why it matters, ✓ 3–5 observations, ✓ Firsthand evidence, ✓ Reflection, ✓ Scope, ✓ Research confirmation, ✓ Team Charter if applicable.

Reviewer then answers: **Are these elements merely present, or actually sufficient?**

Rating: (same four levels)

**Platform checks presence. Reviewer checks quality.** — these are different jobs and neither substitutes for the other.

## 6. Communication & Clarity
- ☐ Problem is immediately understandable
- ☐ Affected group is clear
- ☐ Evidence trail is easy to follow
- ☐ Submission stands on its own

Rating: (same four levels)

# PART D — Automated Gate Logic

**Non-negotiables (must all be present):**
- Real affected person/group
- Firsthand evidence
- Problem statement does not contain the solution

**Dimension floor:** all six dimensions must be Meets Standard or Strong Evidence.

The platform calculates the outcome — the reviewer never manually tallies it.

---

**✓ ADVANCE**

> Stage 1 complete. Your problem is sufficiently validated to justify deeper investigation.

- **What your reviewer needs to see** — each resubmission expectation

# Architecture Feature: Evidence IDs

Every saved evidence item receives a permanent internal identifier:
- **OBS-XXX** — observation
- **INT-XXX** — interview
- **SRC-XXX** — secondary source (Stage 2+)
- **TEST-XXX** — experiment/test (Stage 4+)
- **RES-XXX** — impact result (Stage 5+)

Students don't need to think about these IDs — the platform does. This is what eventually enables a full evidence trail:

**Final Pitch Claim → Impact evidence → Stage 4 test → Stage 3 decision → Stage 2 research → Stage 1 observation/interview**

This is one of the most distinctive features of the entire platform: **every claim has an evidence trail.**
