# i3League — Stage 5: IMPACT — Activities

## By Topic

| Topic | Activity | Worksheet | Output | Artifact Contribution |
|---|---|---|---|---|
| What Does Impact Mean? | Impact in One Sentence — complete "Because of our solution, ___ changed for ___." | Impact Statement Builder | 1 clear impact statement | Impact Report |
| Choosing the Right Success Metric | Measure What Matters — compare several possible metrics and choose the one that best reflects the original problem | Success Metric Selector | Selected metric + justification | Impact Report |
| Baseline / Benchmark / Comparison vs. Result | Before vs. After — document your reference point (a before-state baseline, benchmark, control/comparison condition, or existing standard, as appropriate to your project) and compare it with the measured result | Baseline / Benchmark / Comparison Sheet | Reference point/result comparison | Impact Report |
| Quantitative vs. Qualitative Evidence | Numbers + Stories — pair at least one quantitative result with one qualitative observation, quote, or story | Quantitative / Qualitative Evidence Table | Mixed-evidence summary | Impact Report |
| Data Analysis & Interpretation Basics | What Else Could Explain This? — identify patterns, anomalies, and at least one alternative explanation for the result | Data Interpretation Worksheet | Written interpretation + alternative explanation | Impact Report |
| Responsible Claims | Claim Audit — compare every major impact claim against the actual evidence and rewrite anything overstated | Responsible Claims Check | Evidence-aligned claims | Impact Report |
| Limitations & Research Integrity | Name the Weak Spot — identify sample, timing, location, method, or other limitations honestly | Limitations Log | Limitations section | Impact Report |
| Unintended Consequences | What Else Changed? — look for positive, neutral, or negative effects you did not originally intend to create | Unintended Consequences Check | Side-effect findings | Impact Report |
| Impact Across Stakeholders | Who Benefited, Who Didn't? — compare effects across affected stakeholder groups | Stakeholder Impact Matrix | Stakeholder-by-stakeholder impact view | Impact Report |
| Cost vs. Benefit | Was It Worth It? — compare money, time, effort, materials, and other resources against the benefit produced | Cost vs. Benefit Worksheet | Cost-benefit summary | Impact Report |
| Correlation vs. Causation *(HS CORE)* | What Else Changed? — identify competing explanations and decide how strongly you can claim the solution caused the result | Data Interpretation Worksheet | Causation-strength statement | Impact Report |
| Leading vs. Lagging Indicators *(HS CORE)* | Early Signal vs. Final Result — identify one leading and one lagging indicator | Success Metric Selector | Leading/lagging indicator pair | Impact Report |
| Adoption, Uptake & Usage Metrics *(HS CORE, when relevant)* | Did It Stick? — track whether people continued using, following, or implementing the solution after the initial test | Adoption / Uptake Tracker | Adoption/uptake evidence | Impact Report |
| Scalability *(HS CORE)* | 10× Test — imagine the project operating at ten times the pilot size and identify what would break or need to change | Scalability Check | Scalability risks + changes needed | Impact Report |
| Cost per User / Cost per Use / Pilot Cost | Break Down the Cost — calculate pilot cost and, where relevant, cost per person/use/beneficiary | Cost per User / Use Calculator | Simple cost metric | Impact Report |
| Unit Economics & ROI *(HS CORE, where applicable)* | Is the Return Worth It? — calculate simple ROI or unit economics only where the project supports a meaningful calculation | ROI / Unit Economics Worksheet | ROI/unit-economics summary | Impact Report |
| Advanced Causal Analysis / Forecasting *(STRETCH)* | Strengthen the Claim — design a stronger comparison, causal check, or forecast using available data | Advanced Analysis Planning Sheet | Advanced analysis plan/result | Impact Report, Stretch evidence |

## Supporting Activities

| Activity | Worksheet | Output | Why it's needed |
|---|---|---|---|
| Impact Evidence Collection Plan | Success Metric Selector + Baseline / Benchmark / Comparison Sheet | What will be measured, when, from whom, and how | Prevents students from trying to invent a reference point after the pilot |
| Evidence Quality Check | Evidence Tracker + Responsible Claims Check | Check for missing, weak, biased, or unsupported evidence | Keeps the Impact Report credible |
| Final Impact Conclusion | Impact Statement Builder | Supported / partially supported / not supported conclusion | Forces students to state what the evidence actually proved |

A project should still be able to advance if the result is: **"Our solution did not create the impact we expected."** If that conclusion is supported by good evidence, that is still strong innovation work.

## Stage 5 Output Rollup

Impact Statement + Success Metric + Reference Point (Baseline/Benchmark/Comparison) + Results + Quantitative/Qualitative Evidence + Interpretation + Limitations + Unintended Consequences + Stakeholder Impact + Cost Analysis combine into the required artifact:

**Impact Report**

HS/advanced projects may additionally include: Adoption/Uptake + Scalability + ROI/Unit Economics + Advanced Analysis

## Advancement Check for Stage 5

Student can show:
- a meaningful success metric tied to the original problem
- a credible reference point (baseline, benchmark, or comparison condition) and result
- quantitative and qualitative evidence where applicable
- honest interpretation of the results
- limitations and alternative explanations
- unintended consequences considered
- relevant stakeholder impacts considered
- cost relative to benefit
- a conclusion that matches the evidence, even if the expected impact was not achieved

---

## Required Sequence

**Define Impact → Choose Metric → Establish Reference Point (Baseline/Benchmark/Comparison) → Measure Result → Analyze → Challenge Your Own Conclusion → Check Stakeholders & Side Effects → Consider Cost → State What the Evidence Actually Supports → Advance**

**Guiding principle:** A project does not have to prove success. It has to prove learning with credible evidence.
